# Как объяснить проект

Ниже разбор, чтобы самому понимать код и спокойно показать сайт. Лучше открыть файлы и пройти этот путь один раз руками.

## Что сказать в начале

Я сделал простой сайт с товарами. Он написан на Django, данные хранятся в MySQL. На главной странице есть товары и поиск по названию. У каждого товара отдельная страница. Товар можно добавить в корзину, поменять количество или убрать. Потом можно оставить имя и телефон. Заказ сохранится в базе, и его будет видно в админке.

Я оставил только основные вещи. Здесь нет оплаты картой, регистрации покупателей и доставки. Корзина нужна для выбора товаров, а оформление просто сохраняет заказ для просмотра в админке.

## Как запустить на другом компьютере

Нужны Python и MySQL или MariaDB. Распаковываю архив, создаю окружение командой python -m venv .venv и ставлю зависимости командой .\.venv\Scripts\python.exe -m pip install -r requirements.txt. Файл chotochoto.sql импортирую в MySQL, например через phpMyAdmin. В нем уже есть таблицы и товары. Потом запускаю .\.venv\Scripts\python.exe manage.py runserver. Сайт открывается по адресу http://127.0.0.1:8000/, админка по адресу http://127.0.0.1:8000/admin/. Если у MySQL стоит пароль, перед запуском задаю DB_PASSWORD в окружении.

## Как устроен проект

manage.py запускает команды Django. Например, через него запускается сервер.

config/settings.py содержит настройки сайта. Там указано подключение к MySQL, язык, часовой пояс, папки для обычных файлов и фотографий. По умолчанию база называется chotochoto и работает на 127.0.0.1:3306. Если на другом компьютере пароль от базы есть, его передают через DB_PASSWORD.

config/urls.py задает два основных направления. Адрес admin/ открывает админку. Все остальные адреса передаются в приложение shop.

shop/urls.py связывает адреса сайта с функциями из views.py. Например, / открывает каталог, /cart/ открывает корзину, /checkout/ открывает оформление.

shop/models.py описывает данные в базе. shop/views.py содержит действия страниц. shop/admin.py добавляет товары и заказы в админку. Папка shop/templates/shop содержит HTML страниц. В shop/static/shop/style.css лежат стили. Фото товаров лежат в media/products.

Файл chotochoto.sql нужен, чтобы перенести базу на другой компьютер. Там уже есть пять товаров. Потом товары можно менять через админку.

## Что хранится в MySQL

У меня две свои таблицы: shop_product и shop_order. Остальные таблицы создает сам Django для админки, пользователей и сессий.

shop_product хранит название товара, короткий адрес slug, описание, цену и путь к фото. Slug нужен, чтобы у товара был адрес вида /product/logitech-m185/. Цена хранится как DecimalField, то есть десятичное число для денег.

shop_order хранит имя покупателя, телефон, список выбранных товаров текстом, общую сумму и дату создания. Я оставил заказ одной записью, потому что для этого проекта достаточно увидеть в админке, что выбрали и как связаться с человеком.

models.py не создает таблицы сразу после написания. Для этого есть миграции в shop/migrations. Команда migrate применяет их к MySQL.

## Как работают страницы

Когда человек открывает главную страницу, функция catalog получает товары из Product. Если в адресе есть q, она оставляет только названия, где встречается введенный текст. Например, поиск Logitech покажет подходящие товары. HTML для этого находится в catalog.html.

Если нажать на товар, откроется product_detail. Функция ищет товар по slug и передает его в product.html. Если такого товара нет, Django показывает страницу с ошибкой 404.

Кнопка добавления вызывает cart_add. В корзине я храню не весь товар, а его id и количество. Эти данные лежат в сессии Django под ключом cart. Сессия привязана к конкретному браузеру, поэтому у двух посетителей корзины разные. Сами товары при показе корзины берутся из MySQL по этим id.

cart_rows собирает строки корзины. Для каждой строки она находит товар, количество и считает стоимость этой строки: цена умножается на количество. Функция cart складывает эти суммы и показывает общий итог в cart.html.

cart_update меняет количество. Если ввести число больше нуля, оно сохранится. Если нажать Убрать, товар удалится из корзины. Ссылка Убрать передает количество 0. После изменения открывается корзина с новым итогом.

На странице checkout человек вводит имя и телефон. Если корзина пустая, сайт отправит его обратно в корзину. Если оба поля заполнены, функция создает Order в MySQL, записывает список товаров и сумму, очищает корзину и открывает страницу спасибо. Оплаты и отправки куда-либо здесь нет.

В форме есть csrf_token. Это стандартная защита Django для отправки формы. В обычном виде страницы этот код не виден. Он нужен, чтобы Django принял отправку формы и не выдал ошибку 403.

## Как работает админка

Админка Django уже готовая. Я зарегистрировал в shop/admin.py две модели: Product и Order. В товарах можно менять название, описание, цену и фото. Для поиска есть поле по названию. У заказов видны номер, имя, телефон, сумма и дата. Сам заказ в админке только для просмотра, чтобы случайно не менять данные покупателя.

После изменения товара в админке каталог берет новые данные из базы. Переписывать HTML или Python для новой цены не надо.

## Как показать работу на защите

1. Открыть главную страницу. Показать карточки товаров.
2. Ввести Logitech в поиск. Объяснить, что фильтр идет по названию товара.
3. Открыть товар, добавить его в корзину.
4. В корзине увеличить количество и нажать Обновить. Показать, что сумма изменилась.
5. Нажать Убрать. Потом снова добавить товар.
6. Открыть оформление, ввести имя и телефон, подтвердить.
7. Открыть админку, раздел Заказы, показать сохраненную запись.
8. Открыть раздел Товары и показать, что данные редактируются там.

## Что могут спросить

Почему Django? В нем уже есть работа с базой, адресами страниц, шаблонами, сессиями и админка. Поэтому для такого сайта не пришлось писать это с нуля.

Почему MySQL? По условию нужна эта база. В ней хранятся товары и заказы. Django подключается к ней через настройки DATABASES.

Зачем models.py? Там написано, какие поля есть у товара и заказа. По моделям Django работает с таблицами в базе.

Зачем views.py? Там решается, что делать при открытии страницы или нажатии кнопки: найти товар, добавить в корзину, посчитать сумму, создать заказ.

Зачем urls.py? Он связывает адрес в браузере с нужной функцией из views.py.

Зачем шаблоны? Это HTML страниц. В них подставляются данные, которые передает views.py. Поэтому одинаковая карточка может показывать разные товары из базы.

Почему корзина не отдельная таблица? Она временная и нужна только до оформления. Для простого сайта хватает сессии. После оформления корзина очищается, а сам заказ сохраняется в MySQL.

Как считается сумма? У каждого товара цена берется из базы. Цена умножается на количество. Потом стоимости всех строк складываются.

Где лежат фото? Файлы лежат в media/products. В базе хранится путь к каждому файлу. Django подставляет этот путь в HTML, и браузер загружает картинку.

Зачем нужен slug? Это короткая часть адреса страницы товара. По ней сайт находит нужный товар.

Что происходит после оформления? В таблице заказов появляется запись с именем, телефоном, товарами и суммой. Корзина очищается. Администратор видит запись в админке.

Что здесь можно улучшить позже? Добавить регистрацию, остатки товаров, доставку и оплату. Сейчас это учебный простой сайт, и эти функции в него не входят.

## Если попросят объяснить по коду

Показываю models.py и говорю, какие поля есть в Product и Order. Потом открываю urls.py и нахожу адрес нужной страницы. После этого открываю одноименную функцию в views.py и показываю, откуда она берет данные и какой HTML шаблон открывает. Например, для корзины это адрес /cart/, функция cart, шаблон cart.html. Для оформления это /checkout/, функция checkout, шаблон checkout.html и запись в Order.
